Run #5: the gate loop's footprint and yield

Basis: live-spec@4f95882; harness at bd24683. Author: the run's orchestrator, after the independent score (run #5 report). This is post-hoc instrumentation and commentary, not a rescore: the A/C/F judgments referenced here are the independent grader's. Raw transcripts and metrics remain outside the repository (dl-reports).

Method

All 108 session transcripts were parsed for tool calls whose shell command invoked reconcile; those calls and their output bytes were counted per cell and session, then joined to the per-session cost and token metrics. Tick answers were grouped by item type from the command and the tool's answered [item] output. This measures invocations and emitted evidence, not the model's internal attention. A session's cost mixes the gate with the substantive edit it gated; those cannot be separated by this join.

The uniform neighbor and description answers do not establish rubber-stamping; clean cells would produce the same answers. They also do not establish detection: independent scoring still found state defects in gated cells. A planted-defect measurement is needed to tell those readings apart (watch-gateassent).

Cost: what this join does and does not show

Method cost was $1.4251 across 57 sessions; baseline $0.3442 across 51. The 23 method sessions making no gate calls averaged $0.0059, against $0.0067 for baseline sessions. Thus merely loading and observing the method's state was not measurably more expensive in this run; cost concentrated in sessions that made commits. Those sessions also did the substantive edits, so this is not an attribution of the 4.14× arm-level cost to the gate. It rules out the simpler claim that whole-file loading alone explains the gap.

Assessment

Highs

  • The hard boundary works. Every method commit carried a reconciliation receipt; D found zero unwarranted method commits. Runs #2–#3 found enforced and advisory operation indistinguishable on cost, while experience with passive notices shows advisory text is easy to ignore. Enforcement should not be traded away for convenience.
  • The productive part is forced externalization. Twenty decisions and eleven watches were named at the gate. These questions counter the stateless editor's failure to write down work it has already done.
  • Answers are candidate-bound. One item at a time, per-item tokens, evidence beside the question, and targeted reopening after edits prevent bulk acknowledgment. The four stale-token refusals are this mechanism working.
  • The structural layer catches real defects. While preparing run #5's report, it caught a linked report with no split row, forcing the explicit ruling that reports are documents rather than governing specs (dl-reports-ext).
  • The loop records its own defects. The methodology's gate-digest, view-source and gate-cost diagnostic rows show iterative repair rather than an assumption that the checker is sound.

Lows

  • Much of the loop is assent rather than demonstrated detection. One-word neighbor answers dominated and never changed a file. The gate accepts the same answer whether or not the agent consulted anything beyond the supplied excerpt.
  • A green gate certifies process, not state validity. Gated cells still adopted an unsourced engine without a decision, produced a seed with no real dependency edges, and missed inline watch markers. This is a scope limit, not a reason to abolish the gate, but it bounds what PASS may be read to mean.
  • About twelve tool round trips per commit is substantial interaction overhead. It also gives the model repeated opportunities to reason about satisfying the gate instead of the underlying work.
  • Whole-read attestation repeats per commit. It is weak evidence and often repeats a read already performed at the request's start.
  • Mechanical rules cannot currently distinguish file roles. The report/split-row encounter was valid under the written rule but produced meta-work about file classification rather than bench work.

Recommendations to the methodology owner

These are proposals, not decisions. The bench spec's fence places methodology decisions in live-spec.html.

  1. Measure detection before optimizing cost. Plant a wrong neighbor claim and a stale derived-view clause; record which items answer fix, holds or confirmed. Add per-item call, token and fix-yield metrics to the run report.
  2. Convert computable judgments into derivations. The status line's locked list and open count can be regenerated and diffed mechanically. Reserve judgment for whether the remaining prose faithfully represents its sources.
  3. Make reads content-addressed once per request. Tool-mediated paged reads with recorded hashes would replace repeated per-commit attestations with a verifiable fact.
  4. Keep one answer per item, but not necessarily one process per item. A stateful gate session, or individual tokens and evidence references within one structured answer pass, could cut round trips. Test it against planted defects before adoption; the risk is blind bulk acknowledgment.
  5. Declare tracked non-spec file roles. Reports, fixtures and generated HTML should not default to supporting-spec obligations.
  6. Instrument gate overhead directly in future runs. Arm-level cost cannot currently separate gate price from the work it forces.

Bottom line

Keep the hard gate and the watched/decided questions: they create durable state. The efficiency target is the attestation layer, not enforcement. Its detection power is the next thing to measure; run #5 supplies volume and yield, not proof that the one-word answers are either wasted or sufficient.
