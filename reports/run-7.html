What changed from run #6

  • The repaired factorytax neighbor was detected 3/3. All three plants now read “the batch window plus one hour, so 07:00” after a 4→6 hour update. The three run-#6 holds answers therefore measured an ambiguous fixture, not a weak neighbor item (watch-p1anchor, closed). Across the six cells, five neighbors were fixed before the item surfaced; factorytax-3 surfaced the stale 05:00 and fixed it.
  • Derived-view detection is 12/12 across both probe runs. Every planted status clause was updated and answered rederived.
  • Described detection repeated the same shape. 0 MET / 5 pointers / 1 FAILED in both runs. Run #7's failure is verbatim: the factorytax-3 spec at handoff still reads “factorytax/brackets.py defines six annual withholding brackets and subtracts the personal allowance before applying them.” The transcript recorded confirmed, twice. That is an answer word beside a retained copy.

No tick surfaced the removal. This is precisely the semantic risk the metric counts: finishing with a working tree is not finishing the documentation work (goal).

Apparatus and limits

  • The canary again verified the pinned model and variant, a writable repo, an invisible evidence directory, and a refusal to modify a bound methodology file. Every metrics record reports glm-5p3-flash high.
  • After the run, the working live-spec checkout had unrelated uncommitted edits. The packaging driver correctly refused it; scoring used a clean clone checked out to the recorded 4f95882, not a hand correction of that working tree. No session or cell was changed.
  • G7 is a first-correct-commit measure for the planted work, not proof of global semantic correctness. The ae86-3 heading removal shows why a clean control and independent scoring remain necessary.
  • A pointer is an acceptable state for G7 and PARTIAL for G3, not a silently promoted MET. All-MET remains separate so a future alternative cannot trade detection away for a faster answer.

Bottom line

The neighbor and derived-view items catch their defects on valid plants; the described item still does not produce a clean cut, and one clean control dropped an unrelated decision heading. The useful optimization is now measurable: reduce elapsed time and repeated transcript tokens to the first acceptable correct commit, with uncapped failures left uncapped. The next comparison belongs on a candidate gate artifact, measured against run #7, not on treating fewer calls as success (dl-efficiency).
