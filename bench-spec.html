lspec bench

Status: live-system. Locked: the sandbox (dl-sandbox), one synthetic home per session (dl-home), the pinned model (dl-model), the twelve-cell two-arm design for outcome runs (dl-baseline), the planted-defect probe run (dl-probe), the run order (dl-order), the artifact under test as a run input (dl-artifact), this repository as the harness's own (dl-island), raw evidence outside the repo, summaries tracked (dl-reports), keys never tracked (dl-keys). Open: seven items (open items). Top risk: the held-out briefs (dl-heldout) have never run — the rules stay fitted to the deck they were tuned on. This status line is a derived view. When reporting recorded state, attribute it to the spec; when changing state, re-derive the line whole from the locked list, open table, and top-risk source. Delete a clause with no source, and surface any contradiction with its sources.

Ethos: fix the apparatus, never score around it — a harness defect is repaired in the harness, recorded here as a watch entry, and the affected cells re-run; a run is never corrected by hand.

Conventions: read main whole before acting. Read a supporting spec whole when work crosses into it; every supporting file needs a split row at its parent. No partial loads. Keep each file short. Every value lives once in Key Parameters or is indexed from its authority: artifacts establish actual behavior, approved requirements and decisions establish required behavior, verification evidence establishes conformance. Status tokens: confirmed(source) / provisional(source) / locked / open / WATCH. Git holds history; body text states current conditions and links to rationale. Authority: the scripts and configs in this repository establish what the harness does; this spec indexes them; the checkout named by LSPEC_SRC is the artifact under test (dl-artifact); the pre-registered rubric and seed inventory establish how a run is scored; run reports establish results (runs).

Decisions: use dl- row ids; open each row's first cell with its id in <code>, the row's visible name, uncounted; keep each cell ≤ 40 words. Replace superseded rows, keeping the displaced choice in the successor's rejected/replaced cell. Retain a row only if a fresh session might re-propose its rejected alternative. For an assumption-dependent lock, name the assumption and reopening condition. Change the fence and log the decision before reintroducing an excluded option. A change to a data-sealed claim is a decision change, recorded in a decision row in the same commit, or a correction with its reason that names the decision it restores, else confirmed by a later session.

Session: load → make one move → update the canonical state → reconcile touched claims and their one-hop neighbors → commit → confirm a clean working tree. Check referrers, cited evidence, copies, counts, status, declared counterparts, dependents, and indexed artifacts; follow up only into neighbors changed by the fixes. Report missing instruction referents; state your interpretation and clarify if alternatives would materially change the edit. If you cannot ask, take the reading that changes least and record the alternative as an open item. Commit types: docs fix seed audit review tool (tool: for a change to a script, config template, brief or subject). Each subject is one typed transition line pointing to rationale; seed and review bodies may hold assessments.

Dependencies: put <a rel="depends-on" href="#target"> inside the dependent claim. Its nearest id'd ancestor names that claim. Both anchors enclose complete claims: use a paragraph, section, or table row; a heading covers only its title. Plain links are navigation. Example: <p id="claim">Cooling assumes <a rel="depends-on" href="#rating">the rating</a>.</p> Compare the target's committed text with the latest review naming the dependent claim, or the edge's introduction if unreviewed. A changed or missing target owes review. Confirm or fix the dependent, then record a review: commit naming comma-separated dependent path#id claims, empty if no edit was needed. Removing or redirecting a dependency of a surviving claim also takes a review: commit, including when its target is deleted together with the edge. Deleting the dependent claim retires its obligations without review. Uncommitted edits do not clear debt. If history is unavailable, fetch it or explicitly re-review against committed state. Keep review history in git.

Tooling: begin with python3 lspec.py start bench-spec.html and follow its output. This repository carries its own copy of the tool and hooks, apart from the copy under test. Without the tool, perform its checks by hand.

Procedure — one run

  1. Substitute oc-inst.json and oc-oper.json from the .tmpl files with the key from ~/.local/share/opencode/auth.json; never commit or copy the key (dl-keys).
  2. Set LSPEC_SRC to the live-spec checkout under test at the run's basis (dl-artifact) and BENCH_EV to a fresh evidence dir (kp-evidence); build $BENCH_EV/sandbox-homes/template (kp-home).
  3. Canary before any real session: methodology read-only, repo writable, $BENCH_EV invisible, a trivial opencode run completes with the pinned model and variant (kp-model).
  4. Stage the subjects (kp-subjects); run all 12 instantiations (kp-cells), then the operating decks on all of them (kp-deck), each session run_session.sh REPO inst|oper BRIEF TAG — driver.sh (kp-driver) runs these phases. Wrap batches in systemd-inhibit (watch-suspend). Stage and verify any material a brief references immediately before that brief, in one fail-closed step with its delivery (diag-staging); after the first cell, verify-route checks each planned session's delivered bytes against the registry and aborts on any miss (watch-misroute). W1 runs only in cells whose seed wired no depends-on edge (dl-w1). A session is complete when its transcript ends in a final text part and the cell's git state matches, whatever the runner's exit code (dl-completion). Between briefs, an open lspec request is adopted by the next brief (dl-adopt); held-out slots run only after a freeze (dl-heldout).
  5. Score from direct git evidence against the pre-registered instruments (kp-scoring), from the package driver.sh score-blind builds, by a grader that did not drive the sessions; write the report outside the repo, then the sanitized summary from driver.sh score's skeleton ($BENCH_EV/report-skeleton.html: sessions, commits and cost filled, criteria to score, no paths) into reports/run-N.html, and index it in runs by that link (dl-reports). Archive the evidence dir (tar -czf beside it) at run end, before any pause (watch-evloss).

Probe run — gate detection

A probe run replaces the operating deck with the two slots of kp-probe on the six method cells; the baseline arm, the held-out pair and A–F scoring do not run. The apparatus is a run's usual one (kp-sandbox, kp-model, kp-evidence); BENCH_PROCEDURE=probe driver.sh all runs it. Detection is the planted defect absent at handoff, not the answer word; the report gives each item's fix rate, calls and tokens (rubric G). It tests detection only: enforcement, one-at-a-time answering and the watched/decided questions are settled in live-spec and are not re-tested (dl-probe).

Open Items

A watch entry is an open-items row whose id starts watch-, its first cell opening with that id in <code>: claim, triggering event, date, and the condition that closes it, set by whoever files it. A [WATCH] marker links to its entry. Mark a dated condition data-watch-until="YYYY-MM-DD"; once it passes, close or extend the entry on purpose. A failure seen once, even if root-caused, gets a watch entry: symptom, date, diagnosis, fix. Add a diagnostic-register row (symptom · tell · fix) when a later occurrence confirms the same diagnosis; repeated symptoms alone do not qualify. Any unresolved work remains in the open list and links to that row. Keep a ruled-out register, each cause with the conditions that ruled it out, when an eliminated cause is re-proposed.

Out of Scope

Judging the methodology: results live in the reports and the decisions they inform live in live-spec.html, not here. The subjects' domain correctness (the swap, the payroll rules) beyond their role as fixed fixtures. opencode internals beyond what the harness relies on (kp-cli, kp-db). Any critique that the harness should be a general evaluation framework: it exists to run this one measurement repeatably.

Record

Git is the record: every session-event is a commit; every full sweep takes an audit: commit. A clean sweep may update bookkeeping; its commit is empty only when no files change. No in-file history.
